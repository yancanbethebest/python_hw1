# COMP7035 Assignment 1 作业要求与解决大纲

## 1. 作业主题

本次作业是 `Programme Review from Messy Records`。目标是读取并清洗多个不一致的数据文件，合并成一份每名学生一行的干净数据表，并基于政策文件中的权重和名额生成课程审核推荐结果。

## 2. 已提供文件

- `Assignment-1.pdf`: 作业说明文件。
- `scores.csv`: 学生成绩数据，包含 midterm、final、project 等成绩字段。
- `students.json`: 学生基本信息，包括 student_id、name、email 等。
- `engagement.log`: 学生参与度/出勤记录，按周记录 sessions。
- `policy.json`: 审核政策，包含成绩权重、审核容量和证据截止时间。
- `hw1_template.ipynb`: 作业 notebook 模板，需要在其中完成分析。

## 3. 作业核心要求

1. 完整读取四个数据文件，展示数据概览和初步问题清单。
2. 清洗并整合数据，最终形成一份一名学生一行的数据表。
3. 输出最终接受的成绩、出勤/参与度信息和加权总分。
4. 根据 `policy.json` 中的权重计算总分。
5. 根据 `review_capacity` 推荐最多指定人数进入 review。
6. 明确展示不确定性和需要人工复核的记录。
7. 提出并回答一个有意义的数据分析问题。
8. 做一个额外分析实验，例如改变冲突处理规则或推荐策略，并比较结果。
9. 生成交付文件：
   - `hw1_<ID>.ipynb`
   - `hw1_<ID>_clean.csv`
   - `hw1_<ID>_report.pdf`

## 4. 初步发现的问题

### students.json

- 学生 ID 基本完整且有效，但有 3 个 ID 前后带空格，需要作为文本 trim 后再合并。
- 部分姓名存在前后空格，需要 trim。
- 部分 email 存在大小写不一致，需要统一小写。

### scores.csv

- 存在重复表头行。
- 存在重复 student_id 记录。
- 存在缺失值和非数字值，例如 `N/A`、`missing`、`abc`、`??`。
- 存在超出合理范围的成绩，例如小于 0 或大于 100。
- 部分重复成绩存在冲突，需要制定规则处理。
- 部分记录带有额外字段，例如 `retake`、`late`，不能直接当作成绩。

### engagement.log

- 存在注释行和空行。
- 部分记录字段数量不正确。
- 部分 student_id 不是八位数字。
- 部分 week 不在 `w1` 到 `w4` 范围内。
- 部分 sessions 不是 0 到 2 的整数。
- 存在 policy 截止时间之后的记录，应单独审计。
- 同一学生同一周可能存在重复或冲突记录。

### policy.json

- 提供成绩权重、审核容量和证据截止时间。
- 未提供明确的最低分数线，因此推荐策略应基于加权总分排名。
- 需要校验权重字段、权重和、review capacity 和 as_of 时间格式。

## 5. 完整数据清洗策略

### 5.1 读取与基础校验

- 四个输入文件都保留原始行号或原始记录，便于之后追溯异常。
- `student_id` 一律按文本读取和保存，不能转成数字；这样才能保留 `04770215` 这类前导零。
- Excel 查看或导入 CSV 时，应使用“数据 -> 从文本导入”，并把 ID 列设置为文本。
- 读取 `policy.json` 后先校验：`score_weights` 是否完整覆盖 `midterm`、`final`、`project`，权重和是否等于 1，`review_capacity` 是否为正整数，`as_of` 是否能解析为时间。
- 加权分使用 Decimal 或等价的精确计算方式，避免浮点误差影响边界排名。

### 5.2 学生身份与档案清洗

- 对所有来源的 `student_id` 先做 trim，再做格式校验和跨文件合并。
- 有效学生 ID 应为八位数字；短 ID 不自动补零，也不猜测缺失的前导数字。
- `engagement.log` 中两条 `4770215` 与 `04770215` 疑似对应，但不能自动合并，应标记 `possible_unmerged_short_id_engagement` 供人工确认。
- `students.json` 原始档案 164 人，trim 后仍为 164 个唯一 ID。
- `students.json` 中有 3 个 student_id 前后带空格：`63339209`、`39369847`、`75579252`。
- `scores.csv` 中也存在 ID 或字段前后带空格，例如 `30026969` 这一行；合并前必须统一 trim。
- 姓名字段 trim，email 统一转小写。
- 不在 `students.json` 中的有效八位 ID 标记为 `missing_profile`，进入人工复核。
- 档案缺失但有成绩的 4 个 ID 是 `63941939`、`71913273`、`78951060`、`98446968`；这些 ID 在 `engagement.log` 中也有参与度记录，因此不能描述为“只在成绩里出现”。
- 另有 2 个 ID 只在参与度中出现：`23990001`、`23990002`。
- `students.json` 中有 6 个档案存在但没有成绩和参与度记录：`23880001` 到 `23880006`，应标记为 `profile_only_no_records` 或 `no_score_no_engagement`，不要和 `missing_profile` 混淆。

### 5.3 成绩清洗

- `scores.csv` 中重复表头和空行不进入成绩计算，但要在质量摘要中计数；当前有 3 行重复表头和 5 行空行。
- 每行按 `student_id, midterm, final, project` 的位置读取。列数不正确的行仍尽量读取前三个成绩字段，但必须标记 `malformed_score_row` 并保留原始行。
- 列数不正确的行有 4 行：`77758700,80,94` 少一列；`98446968,...,x`、`75634387,...,retake`、`11622026,...,late` 多一列。
- 成绩只接受 0 到 100 之间的数字。`N/A`、`missing`、空白、`abc`、`??` 等文本占位符，以及 `104`、`-5`、`999`、`101` 等超范围值全部剔除并写入审计。
- 必须先剔除无效值，再判断同一学生同一字段是否存在有效值冲突。
- 无效值剔除后，真正存在有效成绩冲突的学生是 `68442511`、`32068497`、`19212221`。
- `58124315` 的 `104` 是超范围值，剔除后剩余有效 midterm 为 53，因此不应算作成绩冲突。
- 重复记录中某个成绩字段的有效值一致时，保留该值；有效值不一致时，基线方案采用较低值，并标记 `score_conflict`。
- 冲突值不能丢弃，应记录所有候选值，并在额外实验中检查取高值或取平均值是否改变推荐结果。
- 不对缺失成绩做填补；三个成绩部分不完整时，不计算 `weighted_total`。

### 5.4 参与度清洗

- `engagement.log` 中注释行和空行忽略，但无效数据行需要审计。
- 只保留字段数量正确、时间戳有效、ID 为八位数字、week 为 `w1` 到 `w4`、sessions 为 0 到 2 整数的记录。
- 无效参与度行共有 12 条，包括短 ID、非法 week、sessions 超范围或非整数，以及 `sync failed...` 这类纯文本错误行。
- 使用 `policy.json` 中的 `as_of=2026-09-14T23:59:00` 作为证据截止时间；`recorded_at <= as_of` 的记录进入基线，晚于 as_of 的记录只进入审计。
- 先排除截止时间之后的记录，再判断基线冲突，避免把截止后修订误判为基线冲突。
- 截止后记录共有 16 条，集中在 2026-09-15 到 2026-09-20，应进入审计，并可标记 `post_cutoff_differs_wX` 来说明是否可能改变结果。
- 同一学生同一周重复记录一致时合并；记录冲突时，基线方案采用较高 sessions，并标记 `engagement_conflict_wX`。
- 同时间戳下 sessions 不同的记录不能用“以最新为准”解决，应标记 `same_timestamp_conflict_wX`，取高值进入基线并强制人工复核。
- 截止日前同时间戳冲突包括 `19949173`、`10833913`、`37560471`；其他不同时间戳冲突包括 `10398551 w4`、`42059446 w2`、`58404922 w3`、`94089208 w3`、`45710390 w4`。
- 输出中 `w1_sessions` 到 `w4_sessions` 的空白表示未知，0 表示确认未出勤；同时输出 `weeks_recorded`、`weeks_unknown` 和 `sessions_total_known`，避免把未知误当成 0。

### 5.5 合并与最终表

- 以所有学生级文件中出现的有效八位 ID 的并集作为候选范围，再根据档案状态、成绩状态和参与度状态添加标记。
- 最终表保证一名学生一行，合并学生档案、清洗后成绩、参与度汇总、加权分、推荐结果和人工复核原因。
- 缺档案、只有档案无记录、成绩缺失、成绩冲突、参与度冲突、截止后记录、疑似短 ID、推荐边界等情况都写入 `review_reasons`。

### 5.6 推荐与边界处理

- 仅对成绩完整且档案已核实的学生计算推荐资格；缺档案学生默认不进入推荐，除非人工核实后另行纳入。
- 按 `weighted_total` 从高到低排序，推荐人数不超过 `review_capacity=15`。
- 同分时按 `student_id` 排序，保证结果可复现；但这只是技术性排序，不代表业务优先级。
- 第 15 名和第 16 名同为 83.20 时，应同时标记 `tie_at_cutoff`，避免把任意排序解释成真实差异。
- 推荐边界建议量化为：加权分与第 15 名或第 16 名相差不超过 1 分，或者冲突处理规则可能改变是否入选。
- 出勤作为支持证据和审计信息，不额外加分。

### 5.7 审计与人工复核

- 所有被忽略、修正、剔除、合并或取舍的记录都应可追溯到原始文件和原始行。
- 审计日志至少包含：重复表头、空行、malformed 成绩行、无效成绩值、成绩冲突候选值、无效参与度行、截止后参与度记录、参与度冲突、同时间戳冲突、missing profile、profile only no records、possible short ID match、推荐边界学生。
- 对冲突处理规则做一个额外实验，例如成绩冲突从“取较低值”改为“取较高值”或“取平均值”，比较推荐名单是否变化，并说明公平性影响。
